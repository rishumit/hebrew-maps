## Design Decisions and Assumptions

### `hmaps/__main__.py`
- Env vars (`HMAPS_DATA`, `HMAPS_WEB`) are set **before** any `hmaps.*` import, satisfying the constraint that `settings.py` reads them at module-instantiation time.
- Uses `uvicorn.Config` / `uvicorn.Server` with the string form `"hmaps.api.app:app"` to defer the import of `settings.py` until the server starts.
- `HMAPS_ROUTER=local` is defaulted in frozen mode (no Docker OSRM available in a standalone install).
- Browser opens after polling `/api/health` up to 20 s (40 × 500 ms), matching the pattern in `start-windows.ps1`.
- Console window: when `sys.stdout is None` (PyInstaller windowed mode), a `FileStream` wrapper routes stdout/stderr to `hebrew-maps.log` next to the EXE.

### `installer/hebrew-maps.spec`
- `SPECPATH` resolves to `installer\`, so `Path(SPECPATH).parent` is the project root — all paths in the spec are safe regardless of the working directory.
- `web\` assets are **not** bundled inside the PyInstaller archive. They are kept on disk next to the EXE and copied by Inno Setup. This avoids doubling hundreds of MB of tile/media data.
- `openapi.json` is explicitly listed in `datas` because PyInstaller does not auto-collect non-`.py` files.
- `tzdata` data files are listed in `datas`; uvicorn/starlette use them for timezone handling and PyInstaller misses them.
- `hmaps.etl` and `osmium` are excluded — they are ETL-only, not needed at runtime.
- `console=False` + `windowed=True` produces a `pythonw`-style binary (no black console window on launch).

### `installer/build.ps1`
- Gracefully handles missing Inno Setup: prints instructions and exits 0 (PyInstaller output is still usable).
- `distpath` and `workpath` point inside `installer\` to keep all build artifacts under `installer\dist\` and `installer\build\`.

### `installer/hebrew-maps.iss`
- `AppId` GUID is stable; must not change across versions (upgrade detection).
- `PrivilegesRequired=lowest` → per-user install, no UAC prompt.
- `data\` subdirs use `skipifsourcedoesntexist` — the installer builds even if tiles/routing/DEM haven't been generated yet.
- `data\` is NOT listed in `[UninstallDelete]` — user data survives reinstalls.
- Hebrew ISL (Inno Setup built-in) is listed after English as fallback if the system locale differs.
- `[Code]` section checks `IsWin64()` and shows a bilingual error if run on 32-bit Windows.

## Next Steps for the User

1. **Ensure the venv is set up:**
   ```cmd
   setup-windows.cmd
   ```

2. **Install Inno Setup 6** (if not already installed):
   Download from https://jrsoftware.org/isinfo.php

3. **Run the one-command build** from the project root:
   ```powershell
   powershell -ExecutionPolicy Bypass installer\build.ps1
   ```
   This produces: `installer\HebrewMaps-Setup-1.0.0.exe`

4. **Test the installer** on a clean machine or VM to verify all paths resolve correctly.

   installer/dist/
